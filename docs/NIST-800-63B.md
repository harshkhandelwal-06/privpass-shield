# NIST SP 800-63B (rev. 4) alignment: password verifiers

Each row links the requirement to the code that implements it and the test that proves it.

| NIST requirement (password authenticators) | PrivPass implementation | Evidence |
|---|---|---|
| Minimum 15 characters when the password is the only factor | Policy returned by `/api/auth/breach-ticket`; enforced client-side and re-checked server-side (`_policy_gate`) | `test_gate_fails_closed_and_blocks_breached_and_short_passwords` |
| Allow at least 64 characters | Maximum is 128 | same test (`password_length: 129` rejected) |
| Accept all printing ASCII, space and Unicode; normalise before hashing | `normalizePassword()` (NFKC) before SHA-1, PBKDF2 and vault KDF; server bootstrap also normalises | `static/app.js`, `app/bootstrap.py` |
| Compare against a blocklist of commonly used, expected or **compromised** values | HIBP Pwned Passwords range API (k-anonymity, padded), a local common-password list, and context words (email username, service name); reject on match | `runBreachGate()`, `test_rejected_attempts_are_counted_without_password_data` |
| Fail safely if the blocklist check cannot be completed | "Unavailable" and offline-fixture results are rejected (fail-closed) | `test_gate_fails_closed_…` |
| No composition rules (no forced upper/lower/digit/symbol) | None. The policy object declares `composition_rules: false` | `/api/auth/breach-ticket` response |
| No periodic forced rotation; change on evidence of compromise | No expiry on account passwords. Vault "review reminders" are optional and off by default, with wording that follows NIST | `static/index.html` vault editor |
| Allow paste and password managers | Inputs use `autocomplete` and allow paste; the built-in generator and vault encourage them | `static/index.html` |
| Offer guidance on why a password was rejected | Signup/reset show the specific reason (breached, count, length, unavailable) | `runBreachGate()` |
| Rate-limit failed attempts | Per-IP limits on challenge/login/signup/reset/vault unlock (Redis-backed when configured) | `rate_limited()` |
| Store verifiers salted and hashed with a cost-hard KDF | Client PBKDF2-SHA256 (random 16-byte salt), then server AES-GCM encryption plus Argon2id integrity hash | `app/security.py` |
| Don't use knowledge-based hints | None stored. The forgot-password flow uses a single-use reset token | `/api/auth/reset/*` |

Not in scope for this demo: rev. 4 also covers verifier impersonation resistance (for AAL3) and
secure out-of-band reset delivery. The demo returns the reset token directly when `APP_ENV != production`.
